Product Requirements Document (PRD): PixelRoast
App Name: PixelRoast
Tagline: "Emotional damage on Demand"
Version: 1.0 (MVP)
Target Audience: Junior Developers, UI/UX Students, Boot-campers.
1. Product Overview
PixelRoast is a brutal, AI-powered design critique tool. Users submit their portfolio URLs or resumes, and an AI "Senior Art Director" persona analyzes them using computer vision and LLMs.
The feedback is delivered as a "Roast"—harsh, funny, but ultimately actionable advice, presented in a unique "Clinical Neo-Brutalist" interface.
2. Technical Architecture
The system follows a strict Split Architecture to handle heavy browser automation and security.
2.1 Frontend (Client)
Framework: React 18 + Vite.
Styling: Tailwind CSS (configured for "Light Mode Neo-Brutalism").
Hosting: Cloudflare Pages.
State Management: React Context or Zustand.
Animations: Framer Motion (layout transitions) + Lottie (Mascot).
2.2 Backend (Server)
Framework: FastAPI (Python 3.9+).
Hosting: Hugging Face Docker Spaces (Linux container).
Browser Engine: Playwright (Chromium) for screenshots.
Security:
PII Redaction: Microsoft Presidio (presidio-analyzer, presidio-anonymizer).
Sanitization: Bleach (for HTML stripping).
CORS: Strict allow-list for the Cloudflare domain.
2.3 AI Logic (The Brains)
Routing Logic: The backend switches models based on user.is_premium.
Vision (Portfolios):
Free Tier: meta-llama/llama-4-scout-17b-16e-instruct (Fast, Standard Vision).
Premium: meta-llama/llama-4-maverick-17b-128e-instruct (High-Res, Deep UX Analysis).
Chat/Personality: llama-3.1-8b-instant (All Tiers).
Resume Analysis:
Free Tier: llama-3.3-70b-versatile (Standard Logic).
Premium: moonshotai/kimi-k2-instruct (Long Context for 10+ page resumes).
3. Design Specifications ("The Clinical Critic")
Theme: Light Mode Neo-Brutalism.
Vibe: Sterile, Judgmental, High-Fashion, "Red Pen Correction".
3.1 Color Palette
Canvas: #FFFFFF (Stark White).
Ink (Text/Borders): #050505 (Deep Black).
Accent (The Roast): #FF0033 (Correction Red).
Secondary: #E5E7EB (Light Gray - for technical grids).
Key Features & User Flow
4.1 Feature: The Personality Toggle
Users select a "Roast Master" before scanning.
The Gen Z Intern: Slang-heavy. "This padding is giving depression, no cap."
The Boomer Boss: Corporate jargon. "Let's circle back on why this navbar is unusable."
Gordon Ramsay: Pure rage. "THIS CSS IS RAW! IT'S FROZEN!"
4.2 Feature: The Redemption Arc ("Fix It")
Trigger: After the roast, a "Fix It" button appears next to major errors.
Action: The AI generates the specific Tailwind CSS classes to resolve the issue.
Example: "Error: Button too small. Fix: px-6 py-3 font-bold."
UI: A code snippet block that users can copy-paste directly.
4.3 Feature: Resume Reality Check
Input: File Upload (PDF only).
Process: Parse PDF -> Redact PII (Names, Phones) -> Compare Skills vs. Portfolio.
4.4 Feature: "The Clapback Engine" (Interactive Chat)
**Objective:** Allow users to argue with the AI, ask for clarification, or get roasted further after the initial analysis.
**User Story:**
"As a user whose feelings were just hurt, I want to reply to the AI's critique so I can defend my design choices or ask how to fix them, receiving a reply in the specific persona I selected."
**Functional Requirements:**
1.  **Context Awareness:** The Chatbot must have "read" the initial Roast JSON and the user's specific errors. It cannot be a generic chat; it must reference the specific padding errors or font choices found in step 1.
2.  **Personality Consistency:** The selected persona (Gen Z, Boomer, Ramsay) must persist through the entire chat session.
3.  **Model Routing:** This feature exclusively uses `llama-3.1-8b-instant` (via Groq) for low-latency, real-time replies.
**UI/UX Specifications (The "Toggles"):**
* **Location:** A floating "Intercom-style" chat bubble in the bottom right, but styled brutally (e.g., a jagged speech bubble with a thick black border).
* **The Toggle (Selector):**
    * Instead of a dropdown, use a **3-State Physical Switch** (like a guitar pickup switch or industrial lever) rendered in CSS.
    * **Positions:**
        * `Left`: 🧢 **Gen Z** (Emoji heavy, lowercase).
        * `Center`: 👔 **Boomer** (Caps lock for emphasis, corporate jargon).
        * `Right`: 🤬 **Ramsay** (Red UI accents, pure aggression).
**API & Data Flow:**
* **Endpoint:** `POST /chat`
* **Payload:** `{ "message": "Why is 12px font bad?", "history": [...], "roast_context": {...}, "personality": "ramsay" }`
Note:1.remember to use the same personality as the roast 
     2.use data which is generated by the roast(website scan and resume scan) to save input tokens .
     3.rate limit the chat to 10 request every 60 seconds.
5. Monetization & Rate Limiting
Free Tier:
Limit: 5 Scans Total (Resumes + Websites mixed).
Models: Scout (Vision) / Llama-70b (Resume).
Rate Limit: 1 request every 60 seconds.
Premium Tier:
Limit: Unlimited Scans (Resumes + Websites mixed) (not unlimited , set limit to 50 scan per day).
Models: Maverick (Vision) / Kimi-k2 (Resume).
Features: Access to "Gordon Ramsay" mode (optional lock).
3.2 Visual Language
Hard Edges: 0px border-radius on containers.
Hard Shadows: box-shadow: 4px 4px 0px 0px #000000; (No blur).
Typography:
Headings: Thick, tight-kerning Sans-Serif (e.g., Inter Tight, Helvetica Now).
Data: Monospace (e.g., JetBrains Mono).
Idle: Tapping a clipboard.
Processing: Scribbling furiously with a red marker.
Roast: Throwing papers in the air.
4. Key Features & User Flow
4.1 The Landing Zone (Hero)
Input: A massive, paper-white input field with a thick black border.
Action: Button labeled "JUDGE ME".
Micro-interaction: On hover, the button rotates 2 degrees (stamp effect).
4.2 The Roast Result (Visual Output)
Display: The user's website screenshot is displayed with a dimmed overlay.
Stamps: AI-generated critiques appear as "Stamps" or "Sticky Notes" (CSS overlays) positioned relative to the error.
Effect: SVG animation drawing a red circle around the bad element.
Scorecard: A sidebar showing:
"Emotional Damage Score" (0-100%).
"Typography Crimes" (Count).
4.3 The Resume Reality Check
Input: File Upload (PDF only).
Process:
Parse PDF -> Redact PII (Names, Phones).
Compare Skills ("React Expert") vs. Portfolio Code ("jQuery detected").
Output: A "Hypocrisy Report" highlighting lies.
4.4 Feature Request Board (Airlock)
UI: Kanban-style board.
Security: Inputs are sanitized via Bleach and PII-redacted before DB entry.
Visuals: Upvote buttons look like "Stamps of Approval".
5. Security & Privacy Constraints
No Retention: Screenshots are deleted from RAM immediately after analysis.
PII Shield: No resume text leaves the server without passing through Presidio.
Rate Limiting: 5 requests per IP per hour (Redis/Memory).
